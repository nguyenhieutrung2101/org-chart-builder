# Function Inventory — Org Builder

> Generated by full read of the codebase at commit `fe0ad60` (v9); line numbers re-verified after the dead-code cleanup and the code-review fixes that followed (v10).
> Scope: all source files; `node_modules`, build output, tests and vendored code excluded (none exist in this repo).

## Source files & roles

| File | Lines | Role |
|---|---|---|
| `public/index.html` | 3153 | **The entire application** — single-file app: CSS (l.7–339), HTML (l.341–578), JS (l.580–3151). Served as-is by Cloudflare Workers static assets. |
| `wrangler.jsonc` | ~10 | Cloudflare Workers config (`assets: ./public`). No code. |
| `README.md` | ~70 | Documentation. No code. |

All functions below live in **`public/index.html`**. There is no module system — every top-level `function` is a global. **[PUBLIC]** marks functions that are UI entry points (wired to a DOM event / called from generated DOM) or cross-section APIs; everything else is internal helper.

Conventions used below:
- Types are inferred (the code is untyped ES5-style JS). `NodeId` = string like `n1`; `VNodeId` = `v1`; `Node`/`VNode` = the plain objects stored in `nodes`/`vnodes` Maps; `Layout` = return value of `layout()`.
- "state" = the global mutable state (`nodes`, `rootIds`, `sel`, `focusId`, `fcGroups`, `fcs`, `roleBoxes`, `ruleGrids`, `vlineGrids`, `ruleMode`, `vnodes`, `vroots`, `cigs`, `zoom`, …).
- Side-effect legend: **DOM** (writes DOM), **state** (mutates globals), **undo** (pushes undo snapshot via `snap`), **LS** (localStorage), **DL** (triggers file download), **CB** (clipboard).
